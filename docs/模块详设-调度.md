# 模块详设 · 调度（schedule）— 方法/类级

> 配合 `docs/AI开发提示词.md` §5.6。目标：把"四类触发 + 客户并行/租户聚合 + 错峰 + 防重 + 重试 + CI 门禁"细化到接口与方法。Java 17 + Spring Boot 3 + Quartz/XXL-Job + Redis(Redisson 分布式锁)。

## 1. 职责
按计划/事件/CI/手动触发检测任务，把任务展开为执行单元（独立库=按客户；租户隔离=按租户群一次聚合），调度到执行引擎，控制并发与错峰，保证不重复执行、失败可重试，并为 CI 流水线提供门禁结论。

## 2. 模型与接口

```java
enum TriggerType { CRON, EVENT, CI_GATE, MANUAL }

record DetectTask(Long id, String name, TriggerType triggerType, String cron,

public interface TaskService {

    void pause(Long id); void resume(Long id);
    RunHandle runNow(Long id, String operator);    // MANUAL
    List<RunSummary> history(Long id, Page page);
}

// CI 发布门禁
public interface CiGateService {
    GateResult run(GateRequest req);   // req: 产品线/客户范围/期间/版本/gateSeverity(+是否带回归对比)
}

                  List<RegressionFinding> regressions, String runId, int exitCode) {} // exitCode: passed?0:1
```

## 3. 任务展开与执行（核心）

```
executeTask(task):
   lockKey = "detect:task:"+task.id
   if !lock.tryLock(lockKey, leaseMode): return   // 分布式锁防重复(多实例)
   try:
     units = expand(task.scope)        // 展开执行单元
     submitWithConcurrency(units, task.concurrency)
   finally: lock.unlock(lockKey)

expand(scope):
   for customer in scope.customers(按筛选):
      if customer.mode == DB_PER_CUSTOMER:
          yield Unit(customer, rules=resolveEffectiveRules(customer))      // 1 客户 1 单元
      else: // TENANT_SHARED
          yield Unit(tenantPool=customer, rules=..., aggregated=true)      // 1 租户群 1 单元(聚合扫描)

submitWithConcurrency(units, n):
   pool = bounded executor(n)            // 全局并发上限受集群配置约束
   for u in units: pool.submit(() -> runUnitWithRetry(u))

runUnitWithRetry(u):
   for attempt in 1..3:
      try: run = checkEngine.run(u.scope, u.rules, meta); persist(run);
           if run has FAILED/ERROR: alertService.raise(run);   // 告警在此触发
           return
      catch transient e: backoff(attempt)   // 2 次重试
   markUnitError(u); alertService.raiseTaskFailure(u)          // 仍失败→任务级告警
```

## 4. 触发方式
- **CRON**：Quartz Job 调 `executeTask`；更新 `lastRunAt/nextRunAt`。
- **EVENT**：业务结账完成事件(MQ/Webhook/回调)→匹配"结账巡检"任务→`executeTask`。
- **CI_GATE**：流水线发布前调 `CiGateService.run`（见 §5），同步返回门禁结论。
- **MANUAL**：`runNow` 立即执行（仍走锁与并发控制）。

## 5. CI 门禁流程

```
CiGateService.run(req):
   scope = 按 产品线/客户/版本 选定目标
   run = checkEngine.run(scope, resolveEffectiveRules(...), meta(gateSeverity=req.gate))
   if req.withRegression: run += regressionService.compare(run, auditedBaseline)
   passed = run.maxSeverity == null || run.maxSeverity < req.gate
   return GateResult(passed, run.maxSeverity, run.failed, run.regressions, run.id, passed?0:1)
// 供流水线：HTTP 返回 + exitCode 语义；passed=false 阻断发布
```

## 6. 错峰与并发
- 结账高峰（如每月 5 日）自动提升并发并对大批客户**错峰**（散列到时间窗，避免同刻冲击主库）。
- 全局并发上限按集群配置；单客户连接池上限由数据源模块保证（巡检不压垮主库）。
- 失败重试 2 次（指数退避），仅对"可重试异常(连接超时等)"重试；业务失败(账错)不重试，直接出结果+告警。

## 7. 逻辑完整性检查（自检）
- [ ] 四类触发(CRON/EVENT/CI_GATE/MANUAL)均实现并可用。
- [ ] 分布式锁防重复执行（多实例部署安全）。
- [ ] 独立库按客户并行展开；租户群展开为"一次聚合"单元（不逐租户循环）。
- [ ] 并发上限 + 结账错峰；单客户连接受限不压垮主库。
- [ ] 可重试异常重试 2 次退避，仍失败转任务级告警；业务失败直接出结果。
- [ ] 执行历史、lastRunAt/nextRunAt、状态(运行/排队/暂停)维护正确。
- [ ] CI 门禁返回 passed/maxSeverity/exitCode，可阻断发布；支持带回归对比。
- [ ] 失败检查在执行后触发告警（与告警模块对接）。

## 8. 关键单测
- 多实例并发触发同一任务→仅一个执行（锁生效）。
- 租户群任务展开为 1 个聚合单元而非 N 个。
- 连接超时→重试 2 次后转告警；账务失败→不重试、出结果并告警。
- CI 门禁：存在 CRITICAL→passed=false、exitCode=1；全通过→0。
- 结账高峰：大批客户被错峰而非同刻并发。
