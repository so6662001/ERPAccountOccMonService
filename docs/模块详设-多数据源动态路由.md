# 模块详设 · 多数据源动态路由（datasource）— 方法/类级

> 配合 `docs/AI开发提示词.md` §5.2 与 `.cursor/rules/010-readonly-multitenant.mdc`。目标：把"按客户/租户运行时路由 + 只读安全 + 连接池隔离 + 探活"细化到接口与方法。Java 17 + Spring Boot 3 + HikariCP。

## 1. 职责
按执行上下文把业务库访问路由到正确的数据源（独立库=按客户；租户隔离=按租户群共享库），全程只读、连接池按客户隔离限流、口令加密、探活与健康状态维护。平台库（写）与业务库（只读）严格分离。

## 2. 核心类与接口

```java
// 路由上下文(线程级)
public final class DsContext {
    static void set(DsKey key);     // 进入业务库访问前设置
    static DsKey get();
    static void clear();            // try/finally 中清理, 防泄漏
}
public record DsKey(Long dataSourceId) {}   // 直接定位到 data_source 行

// 动态路由数据源
public class RoutingDataSource extends AbstractRoutingDataSource {
    @Override protected Object determineCurrentLookupKey(){ return DsContext.get(); }
    // targetDataSources 懒加载: 首次用到某 dataSourceId 时构建并缓存 HikariDataSource
}

// 业务数据源注册与生命周期
public interface BusinessDataSourceManager {
    DataSource resolve(Long dataSourceId);          // 取/懒建 HikariDataSource(只读)
    void evict(Long dataSourceId);                  // 配置变更后失效重建
    ProbeResult probe(Long dataSourceId);           // 连接探活
    void closeAll();
}

// 只读门面(供引擎调用), 内部负责 set/clear DsContext
public interface DataSourceFacade {
    BigDecimal scalar(Long dsId, String sql, Map<String,Object> p);
    long countOf(Long dsId, String sql, Map<String,Object> p);
    List<Map<String,Object>> rows(Long dsId, String sql, Map<String,Object> p, int limit);
}
```

## 3. 连接池构建（HikariCP，按数据源隔离）

```
buildHikari(dataSourceRow):
   cfg = new HikariConfig()
   cfg.jdbcUrl = row.jdbcUrl ; driver 按 dbType 选择(MySQL/Oracle/SQLServer/达梦/PG)
   cfg.username = row.username ; cfg.password = CipherService.decrypt(row.passwordCipher)
   cfg.readOnly = true                          // 连接级只读
   cfg.maximumPoolSize = perCustomerMax (默认 5) // 按客户隔离限流, 防巡检冲击主库
   cfg.connectionTimeout = 5s ; cfg.maxLifetime = 30min ; cfg.validationTimeout=3s
   cfg.connectionInitSql = 方言只读会话(如 MySQL: SET SESSION TRANSACTION READ ONLY)
   cfg.poolName = "biz-ds-"+row.id
   return new HikariDataSource(cfg)
```
只读副本优先：`data_source.mode=READ_REPLICA` 优先于 `PRIMARY`；同客户存在副本时路由到副本。

## 4. 只读 SQL 校验（双保险）

```java
public final class SqlReadOnlyValidator {
    static void assertSelectOnly(String sql);
    // 用 JSqlParser 解析: 仅允许 Select(含 CTE/WITH); 拒绝 Insert/Update/Delete/Merge/DDL/Truncate;
    // 拒绝多语句(分号注入)、可疑过程调用; 失败抛 ReadOnlyViolationException(返回 4xx, 不执行)
}
```
执行链：`DataSourceFacade` → `assertSelectOnly` → 设 `DsContext` → JdbcTemplate(只读连接) → 查询超时(queryTimeout) + `maxRows` 限制 → 结果脱敏 → `DsContext.clear()`。

## 5. 访问门面实现要点

```
scalar(dsId, sql, p):
   assertSelectOnly(sql)
   try { DsContext.set(dsId);
         return jdbc.queryForObject(bind(sql,p), BigDecimal.class) }   // 空结果→null
   finally { DsContext.clear() }
rows(dsId, sql, p, limit):
   assertSelectOnly(sql); set ctx; jdbc.setMaxRows(limit); queryForList → 脱敏 → clear
countOf(dsId, sql, p): scalar("SELECT COUNT(*) FROM ("+sql+") t", p)
```
- 命名参数绑定(NamedParameterJdbcTemplate)，自动补 `:period`、`:tenantId`。
- 脱敏：按 `data_source` 或全局配置的敏感字段做掩码。

## 6. 探活与健康

```
probe(dsId):  在副本上执行 SELECT 1 / 方言心跳; 记录 latency; 失败计数
   更新 data_source.status: ONLINE / DELAY(latency>阈值) / FAILED; last_probe_at
定时任务: 每 N 分钟批量探活(并发, 单源超时短); FAILED 触发告警(企业微信运维群) + 重连退避
配置变更(改连接串/口令): evict(dsId) → 下次 resolve 重建
```

## 7. 租户隔离支持
- `data_source.tenant_column` 记录租户字段名（默认 `tenant_id`）。
- 引擎在租户模式注入 `WHERE tenant_id = :tenantId` 或聚合 `GROUP BY tenant_id`（见规则引擎详设 §5）。
- 路由层不感知租户值，仅负责连到"租户群共享库"。

## 8. 逻辑完整性检查（自检）
- [ ] 路由按 dataSourceId 懒建并缓存连接池；配置变更可 evict 重建。
- [ ] 连接级 readOnly + SQL 解析双重只读校验；多语句/DDL/写操作全部拦截。
- [ ] 连接池按客户隔离、限流、超时、maxLifetime、maxRows、queryTimeout 全设置。
- [ ] 只读副本优先；五种方言驱动与心跳/只读会话语句正确。
- [ ] 口令加密存取，任何出口不回显；DsContext 在 finally 清理防泄漏。
- [ ] 探活更新状态并对 FAILED 告警与退避重连。
- [ ] 平台库与业务库 DataSource 完全分离（平台业务事务不串到业务库）。

## 9. 关键单测/集成测试
- 写语句(UPDATE/DELETE/DDL/多语句)→被 `assertSelectOnly` 拒绝。
- 同一线程顺序访问两个不同客户库→路由正确、互不串池。
- 探活：副本不可达→status=FAILED 且触发告警；恢复后→ONLINE。
- maxRows/queryTimeout 生效（大结果被截断、超时中断）。
- 口令在日志/异常/接口响应中不出现明文。
