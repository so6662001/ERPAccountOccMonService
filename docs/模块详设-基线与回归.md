# 模块详设 · 基线与回归（baseline）— 方法/类级

> 配合 `docs/AI开发提示词.md` §5.8。目标：把"不变量指标快照 / 审定 / 回归对比 / 期间锁定 / 重置"细化到接口与方法。这是"迭代防回归"的核心。

## 1. 职责
把"业务上不该变"的关键账务指标（标记 `invariant` 的规则的指标）在某客户/租户群、某会计期间固化为基线快照；新一次运行后将不变量指标与**已审定基线**对比，偏离超容差即判定回归（REGRESSION），并入运行结果参与门禁与告警。已结账期间锁定，重置基线需财务审定并审计。

## 2. 模型与接口

```java
enum BaselineStatus { PENDING, AUDITED }

record Baseline(Long id, Long customerId, String tenantKey, String period,
                String relatedVersion, BaselineStatus status,
                Map<String,BigDecimal> metrics,   // ruleKey 或 ruleKey#metric -> value
                String createdBy, Instant createdAt) {}

record RegressionFinding(String ruleKey, String metric,
                BigDecimal baselineValue, BigDecimal currentValue, BigDecimal diff,
                BigDecimal tolerance, boolean regression) {}

public interface BaselineService {
    Baseline snapshot(SnapshotCmd cmd);          // 从一次运行(或即时执行)抽取 invariant 指标→PENDING
    Baseline audit(Long baselineId, String auditor);   // PENDING→AUDITED (仅 FINANCE/ADMIN)
    Baseline reset(ResetCmd cmd);                // 合法变更后重置基线(需审定+审计)
    List<RegressionFinding> compare(DetectRun run, Long baselineId); // 回归对比
    Baseline current(Long customerId, String tenantKey, String period); // 取当前已审定基线
}
```

## 3. 快照抽取（snapshot）

```
snapshot(cmd):
   run = cmd.runId!=null ? loadRun(cmd.runId) : checkEngine.run(cmd.scope, invariantRules, meta)
   metrics = {}
   for res in run.results where rule.invariant == true and res.status==PASSED:
       name = rule.invariantMetric ?: pickDefaultMetric(res.metrics)   // 默认取 value/left/...
       if name present: metrics[res.ruleKey + (multi? "#"+name : "")] = res.metrics[name]
   b = new Baseline(scope, period, run.label/version, PENDING, metrics, operator)
   save(b); audit(SNAPSHOT_BASELINE); return b
```
- 仅纳入 `invariant=true` 且通过的规则指标（失败/ERROR 的不进基线）。
- 期间从 scope.period 取；记录关联的产品部署版本，便于追溯"哪个版本审定的口径"。

## 4. 回归对比（compare）— 核心

```
compare(run, baselineId):
   b = load(baselineId)
   require b.status == AUDITED            // 仅已审定基线参与回归; 否则跳过并提示
   require !isPeriodLocked(b.period) || b.period==run.period  // 已结账期间锁定: 只读对比, 不改基线
   findings = []
   for (key, baseVal) in b.metrics:
       rule = ruleOf(key)
       tol  = rule.invariantTolerance ?: defaultTolerance
       cur  = currentMetric(run, key)     // 当前运行对应指标
       if cur == null: findings.add(error("缺少当前指标", key)); continue
       diff = cur - baseVal
       findings.add(new RegressionFinding(key, metricName, baseVal, cur, diff, tol, abs(diff) > tol))
   // 并入运行: 每个 regression=true 生成一条 category=regression 的 CheckResult(severity 按规则/配置)
   run.merge(findings → CheckResults); run.recomputeSummaryAndGate()
   return findings
```
要点：
- 回归项作为 `CheckResult(category=regression)` 合入 `DetectRun`，参与 `maxSeverity`、门禁与告警。
- 严重级别：回归默认 HIGH（可配/按规则），CI 门禁据此可阻断发布。

## 5. 期间锁定与重置

```
isPeriodLocked(period): 该客户该期间是否"已结账"(来自客户会计期间设置)
reset(cmd):  // 合法变更后(如准则调整)更新基线
   require role in {FINANCE, ADMIN}
   newBaseline = snapshot(asAudited=false) 后 audit(...)   // 走审定
   旧基线归档(保留历史, 不物理删除); audit(RESET_BASELINE, 变更说明)
```
- 已结账期间：基线锁定，只做回归对比，不允许悄悄改基线；如确需改，必须 `reset` 并审定留痕。

## 6. 逻辑完整性检查（自检）
- [ ] 仅 `invariant=true` 且通过的规则指标进入快照；多指标用 `ruleKey#metric` 区分。
- [ ] 审定流程(PENDING→AUDITED)，仅 FINANCE/ADMIN 可审定/重置。
- [ ] 回归对比仅用 **已审定** 基线；容差判定；缺失当前指标→标记错误不静默。
- [ ] 回归项并入运行结果，参与 maxSeverity/门禁/告警。
- [ ] 已结账期间锁定基线；重置需审定 + 审计 + 归档旧基线。
- [ ] 关联部署版本记录，便于追溯口径审定来源。

## 7. 关键单测
- 注入收入指标 +¥2000（v3.8 后）→ compare 标 REGRESSION，运行 maxSeverity 升级、门禁 fail。
- 未审定基线→compare 跳过并提示，不误判。
- 已结账期间→基线锁定，compare 不改基线；reset 需 FINANCE 角色且审计。
- 仅 invariant 规则进快照；失败规则的指标不进基线。
