# 模块详设 · 规则引擎（engine）— 方法/类级

> 配合 `docs/AI开发提示词.md` §5.5 使用。目标：把"声明式规则 → 可执行检查"的引擎细化到接口与方法签名，消除歧义。Java 17 + Spring Boot 3。

## 1. 职责
对给定执行范围（某客户 / 某租户群）按选定规则集合执行检查，产出一次 `DetectRun`（含每条 `CheckResult` 与违规样本），保证：只读、容差、租户过滤、版本生效过滤、异常隔离、租户高效聚合扫描。

## 2. 核心类与接口

```java
// 执行上下文：携带数据源访问、范围、默认参数
public record CheckContext(
    DataSourceFacade ds,          // 只读访问门面(见 §4)
    ExecScope scope,              // 客户/租户群/期间
    BigDecimal defaultTolerance,  // 默认 0.005
    int sampleLimit               // 违规样本上限，默认 20
) {}

public record ExecScope(
    Long customerId,
    IsolationMode mode,           // DB_PER_CUSTOMER | TENANT_SHARED
    String tenantColumn,          // 租户隔离字段名
    List<String> tenantKeys,      // 租户群下的租户(可空=全部)
    String period,                // 会计期间, 如 2026-06
    String deployVersion          // 客户当前部署版本(用于版本判定)
) {}

// 单条规则的运行期模型(已从 rule + customer_rule 覆盖合并)
public record RuleSpec(
    String ruleKey, String name, RuleCategory category, RuleType type,
    Severity severity, BigDecimal tolerance,
    String sql, String leftSql, String rightSql,     // 按 type 取用
    BigDecimal min, BigDecimal max,
    String leftDatasource, String rightDatasource,   // 跨系统用
    Scope scope, boolean invariant, String invariantMetric
) {}

// 机制执行器(策略)
public interface CheckExecutor {
    RuleType type();
    CheckResult execute(RuleSpec rule, CheckContext ctx);  // 不抛业务异常，异常由引擎兜底
}

// 引擎门面
public interface CheckEngine {
    DetectRun run(ExecScope scope, List<RuleSpec> rules, RunMeta meta);
}
```

`CheckResult` 字段：`ruleKey,name,category,severity,status(PASSED|FAILED|ERROR|SKIPPED),message,metrics(Map),samples(List),durationMs,error`。

## 3. 引擎主流程（DefaultCheckEngine.run）

```
run(scope, rules, meta):
  run = new DetectRun(meta, scope); run.start()
  effectiveRules = rules.filter(r -> VersionGate.effective(r.scope, scope))      // 版本/产品/服务器过滤
  skipped = rules - effectiveRules → 记 SKIPPED(reason)
  ctx = new CheckContext(dsFacade, scope, defaultTolerance, sampleLimit)
  if scope.mode == TENANT_SHARED:
      results = runTenantAggregated(effectiveRules, ctx)     // 高效聚合扫描，见 §5
  else:
      for r in effectiveRules:                                // 独立库：逐规则
          results.add( safeExecute(r, ctx) )
  run.addAll(results); run.addAll(skippedResults)
  run.computeSummary()    // total/passed/failed/errored/skipped/maxSeverity
  run.gatePassed = run.maxSeverity == null || run.maxSeverity < meta.gateSeverity
  run.finish(); return run

safeExecute(r, ctx):
  executor = registry.get(r.type)   // 未知类型→ERROR
  t0=now
  try: res = executor.execute(r, ctx)
  catch e: res = CheckResult.error(r, "执行异常: "+e)   // 异常隔离
  res.durationMs = now-t0; return res
```

并发：独立库内可对规则分组用线程池并行（受 `ctx` 数据源连接池上限约束）；多客户由调度层并行（见调度模块）。

## 4. 只读数据访问门面 DataSourceFacade

```java
public interface DataSourceFacade {
    BigDecimal scalar(String datasource, String sql, Map<String,Object> params); // 首行首列, null→null
    long countOf(String datasource, String sql, Map<String,Object> params);      // 包成子查询 COUNT(*)
    List<Map<String,Object>> rows(String datasource, String sql, Map<String,Object> params, int limit);
}
```
实现要点：
- 路由到只读副本；强制 `SqlReadOnlyValidator.assertSelectOnly(sql)`；查询超时、最大行数。
- 参数绑定（命名参数）；自动补充 `:period`、`:tenantId`（租户隔离时）。
- 返回行做脱敏（可配置敏感字段掩码）。

## 5. 租户隔离高效聚合扫描（runTenantAggregated）

```
对每条规则：
  case scalar_zero / scalar_equality / scalar_range:
      改写为按 tenant_id 分组的聚合，HAVING 违反条件 → 得到"异常租户集合 + 指标"
      未在异常集合中的租户判定 PASSED；异常租户生成 FAILED(metrics)
  case rows_empty:
      SELECT tenant_id, COUNT(*) c FROM (违规查询) GROUP BY tenant_id  → 异常租户
      仅对异常租户执行原违规查询 LIMIT sampleLimit 取样本
  case cross_system_*:
      左右两源分别按 tenant_id 聚合后在内存按 tenant_id 比对差额>容差
规则：一次聚合 SQL 覆盖全租户；仅异常租户下钻；禁止逐租户循环单查。
聚合 SQL 改写由 TenantAggregateRewriter 完成（按方言生成）。
```

## 6. 各执行器要点

| type | 通过条件 | metrics | 失败信息 |
|---|---|---|---|
| scalar_zero | `abs(v) <= tol` | value,tolerance | 期望约0，实际 v |
| scalar_equality | `abs(left-right) <= tol` | left,right,diff,tol | 两侧不一致+差额 |
| scalar_range | `min<=v<=max`(空界忽略) | value,min,max | 越界方向 |
| rows_empty | `count==0` | violations | 违规数+抽样 |
| cross_system_scalar_equality | `abs(l-r)<=tol` | left,right,diff,数据源 | 跨系统不一致 |

边界：标量 NULL→0；`rows_empty` 先 `countOf` 再按需 `rows` 抽样；`invariant` 规则把 value 写入 metrics 供基线回归取用。

## 7. 版本生效判定 VersionGate / VersionSpec

```java
public final class VersionSpec {
    static VersionSpec parse(String expr);           // ">=v3.0" | "<=v9.0" | "=v4.0" | "[v3.2,v9.0)" | "*"/null
    boolean matches(String deployVersion);           // 语义化按数值段比较, v9<v10
}
public final class VersionGate {
    static boolean effective(Scope s, ExecScope cust){
        return (s.products.isEmpty() || s.products.contains(cust.productLine))
            && (s.servers.isEmpty()  || s.servers.contains(cust.serverGroup))
            && VersionSpec.parse(s.versionExpr).matches(cust.deployVersion);
    }
    static String skipReason(...);   // 给前端展示"版本未达 v4.0/产品不匹配/服务器不匹配"
}
```

## 8. 逻辑完整性检查（本模块自检）
- [ ] 5 种执行器齐全且各有单测；金额容差；NULL→0 口径一致。
- [ ] 只读校验、参数化、超时、最大行数、样本脱敏到位。
- [ ] 租户隔离全部走聚合扫描 + 异常下钻，无逐租户循环。
- [ ] 版本/产品/服务器过滤正确，SKIPPED 带原因；客户升级后自动生效。
- [ ] 单条规则异常→ERROR 不中断；汇总与门禁(maxSeverity≥gate→fail)正确。
- [ ] invariant 指标写入 metrics 供回归；跨系统能连两源。
- [ ] 多方言(MySQL/Oracle/SQLServer/达梦/PG)聚合改写正确。

## 9. 关键单测用例
- 借贷不平(scalar_zero 失败) / 应收勾稽相等(scalar_equality 通过与失败) / 单价为负(scalar_range) / 逐凭证不平(rows_empty 抽样) / 跨系统不一致。
- 租户群：268 租户一次聚合定位 2 个异常租户，仅这 2 个下钻。
- 版本：`>=v4.0` 规则在 v3.8 客户 SKIPPED，在 v4.1 客户执行。
- 异常隔离：坏 SQL → ERROR，其余规则正常。
